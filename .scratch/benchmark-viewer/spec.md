# Spec: Benchmark Viewer（Terminal-Bench 4.0 成本与分数散点图）

术语以项目根目录的词汇表为准：**榜单行**、**成本**、**价格**、**补充视图**、**预算档**、**最优前沿**、**无价格模型**。决策的完整依据在地图的各工单里，本 spec 只写结论。

## Problem Statement

我想知道"在不同的单位成本下，哪个模型在 Terminal-Bench 4.0 上表现最好"。BenchLM 的榜单页只有一张按分数排序的表，没有成本，也没有像 DeepSWE 那样的散点图；官方榜单同样只是一张表。要回答我的问题，需要把每个榜单行的分数和实测成本放在同一张图上，看出哪些行"又便宜又准"，并且数据要能保持更新、来源合规、局域网里方便打开。

## Solution

一个可 `docker run` 的容器，在局域网内提供一个网页。页面上有一张与 DeepSWE 样式基本一致的散点图：

- **官方视图（主视图）**：数据来自官方 Terminal-Bench 4.0 榜单。Y 轴是官方分数；X 轴是每任务平均实测成本，可切换为每任务平均输出 token、平均单次耗时。图上画出最优前沿，并给出"预算档内最好的榜单行"小表。
- **补充视图**：用 Artificial Analysis 的 Terminal-Bench 4.0 分数与 BenchLM 的输出单价，覆盖官方榜单没收录的模型（含 DeepSeek、Kimi、MiniMax、小米、StepFun 等中国厂商），明确标注它与官方榜单口径不同。
- 页面显示数据截止时间和上次同步时间，并有带冷却的"立即同步"按钮；数据由容器缓存并自动更新，上游故障时继续显示旧数据（直到有新数据替换为止）。

## User Stories

1. 作为使用者，我想在一张图上同时看到每个榜单行的分数和每任务成本，以便判断哪些配置性价比高。
2. 作为使用者，我想让 X 轴反向（越便宜越靠右），以便"又便宜又准"的点落在右上角，和 DeepSWE 的读图习惯一致。
3. 作为使用者，我想看到同一模型的不同推理档位用同色系深浅连成一条线，以便看出加大推理强度带来多少分数和多少成本。
4. 作为使用者，我想看到每个点旁边有"模型名加小字档位"的标签，以便不用悬停就能认出它。
5. 作为使用者，我想悬停在点上看到模型、智能体框架、档位、分数与置信区间、成本、输出 token、耗时和发布日期，以便获得完整信息。
6. 作为使用者，我想在成本、输出 token、平均单次耗时之间切换 X 轴，以便从不同维度比较。
7. 作为使用者，我想在图上看到最优前沿线并让前沿上的点加粗，以便一眼看出每个成本下最好的选择。
8. 作为使用者，我想在图下看到"预算档内最好的榜单行"小表（≤$5、≤$10、≤$15），以便直接读出某个预算下该选谁。
9. 作为使用者，我想按模型勾选、按档位开关来筛选榜单行，并看到"已选/总数"计数，以便聚焦我关心的模型。
10. 作为使用者，我想用"全选"和"清空"一键重置筛选，以便快速开始比较。
11. 作为使用者，我想看到没有数据的档位被划掉且不可点，以便知道该模型没有跑过这个档位。
12. 作为使用者，我想在"全部榜单行"和"每个模型只取最佳档"之间切换，以便在完整视图和简洁视图之间选择。
13. 作为使用者，我想默认看到全部榜单行，以便不会因为默认隐藏而错过低档位的高性价比点。
14. 作为使用者，我想悬停时才看到置信区间，以便图不被误差线弄乱，又能确认分数差是否显著。
15. 作为使用者，我想在图下看到"分数接近的行在统计上分不出高下"的提示以及实际的置信区间范围，以便不被榜首的微小差距误导。
16. 作为使用者，我想在 X 轴标题旁看到 ⓘ 图标，悬停说明成本的计算方式和口径未验证，以便不把它当作模型单价。
17. 作为使用者，我想在页面顶部看到"官方数据更新于 <日期>"，以便知道数据截止到什么时候。
18. 作为使用者，我想看到"上次同步 N 分钟前"，以便知道容器最近一次拉取数据的时间。
19. 作为使用者，我想点击"立即同步"让容器重新拉取数据，以便在得知有新模型时马上看到。
20. 作为使用者，我想在同步完成后看到明确结果，例如"已同步，官方数据无更新（仍为 <日期>）"，以便不会误以为按钮坏了。
21. 作为使用者，我想在同步失败时看到原因和失败时间且旧数据保持可用，以便知道发生了什么。
22. 作为使用者，我想在冷却中看到按钮禁用并显示还需等待多久，以便知道为什么不能再点。
23. 作为使用者，我想在"上次同步"超过 48 小时时看到黄色警告，以便知道自己看的可能是陈旧数据。
24. 作为使用者，我不想在官方数据本身很旧时被警告，因为那只是官方还没更新。
25. 作为使用者，我想切换到补充视图，以便查看官方榜单没收录的模型。
26. 作为使用者，我想在补充视图顶部始终看到"分数来自 AA 的独立评测，与官方榜单口径不同"的横幅，以便不把两份分数混着比较。
27. 作为使用者，我想在补充视图里看到用不同形状标出的"官方榜单也收录了这个模型"，以便识别两套评测之间的差别。
28. 作为使用者，我想在补充视图里看到"已排除 N 个无公开价格的模型"，并能悬停看到名单，以便知道哪些模型没画。
29. 作为使用者，我想在补充视图的 X 轴标题里看到"输出单价，不是每任务成本"，以便不把单价当成任务花费。
30. 作为使用者，我想补充视图也画最优前沿线并注明"按单价"，以便找到单价与分数的性价比边界。
31. 作为使用者，我想按厂商筛选补充视图里的模型，以便集中看某一家。
32. 作为使用者，我想页面在浅色与深色主题之间切换并默认跟随系统，以便在不同环境下舒适阅读。
33. 作为使用者，我想在官方视图看到"官方榜单只收录维护者评测过的模型，其他请看补充视图"的说明，以便理解为什么某些中国模型不在主图里。
34. 作为使用者，我想在页脚看到数据来源、许可和"本页对成本做了计算"的署名信息，以便满足合规要求。
35. 作为局域网内的同事，我想用浏览器直接打开这个页面而不需要装任何东西，以便共享同一份数据。
36. 作为运维者，我想用一条 `docker run` 命令启动，并能改端口，以便和本机其他服务共存。
37. 作为运维者，我想让容器随 Docker 一起自启并有健康检查，以便无需人工看护。
38. 作为运维者，我想让上游访问频率与访问人数无关，以便持续满足合规底线。
39. 作为运维者，我想让上游故障时页面仍然可用，以便官方接口偶尔不可用时不影响使用。
40. 作为运维者，我想让"立即同步"的冷却由服务端强制、局域网共用，以便任何人都不能绕过冷却打上游。
41. 作为运维者，我想让代理只转发白名单里的固定请求，以便容器不会变成开放代理。
42. 作为使用者，我想在数据加载失败且没有任何缓存时看到友好的错误提示和重试入口，以便知道该怎么办。
43. 作为使用者，我想让页面不依赖任何外部 CDN，以便离线的局域网也能用。
44. 作为使用者，我想浏览器记住我选的主题，以便下次打开不用重选，即使本地存储不可用页面也能正常显示。

## Implementation Decisions

### 数据来源与合规

- **Y 轴分数只用官方榜单**，不设回退；若官方数据不可用，功能降级并提示，不悄悄换成别的口径。
- 官方榜单通过其**公开 REST 接口**获取：`POST https://api.harborframework.com/functions/v1/leaderboard-read`，请求体固定为 `{"package":"terminal-bench/terminal-bench","name":"4-0-0","page":1,"page_size":100}`，公开榜单免 key，实测一页取完 27 行。
- **一律不解析任何页面 HTML**（用户决定，合规优先）。BenchLM 使用其公开的 `/data/*.json` 静态文件，**不使用 `/api/`** 路径（其 robots.txt 对 `/api/` 有 Disallow）。
- BenchLM 只需要两个文件：模型文件（含 Artificial Analysis 分数字段、厂商、发布日期、slug）和价格文件（输出单价）。
- 数据只在运行时缓存，**不烘进镜像**，也不做历史快照。
- 请求上游时带可识别的 User-Agent，声明这是内部局域网工具。
- 许可与署名：BenchLM 数据为 CC BY-NC 4.0，仅限非商业；页面必须署名并附链接、许可链接，并注明对数据做了计算和格式转换。官方榜单无强制署名，但页脚同样标注来源与方法说明链接。

### 容器与运行

- 单个容器，基于 OpenResty（含 Lua）；页面是纯静态前端，无后端服务、无 cron、无同步脚本。
- 仅局域网访问，不上公网；默认对外端口 8088（本机 7860 已被占用），可用 `docker run -p` 更改；启动策略为随 Docker 自启，带健康检查。
- 图表库用 D3 的比例尺与线段模块，加原生 JS，无构建步骤；D3 文件随仓库分发，不依赖外部 CDN。

### 代理与缓存（对外接口契约）

- `GET /api/leaderboard`：容器向官方接口发出上述固定请求并返回其 JSON；请求体写死在容器配置里，不接受客户端传入。
- `GET /api/benchlm/<文件>.json`：只放行白名单里的两个 BenchLM 文件，其余路径一律拒绝。
- `POST /api/refresh`：见下节。
- 缓存时长：官方榜单 6 小时；BenchLM 数据 24 小时。缓存过期后，上游故障、超时、403、429 或 5xx 时继续返回旧数据。**只缓存状态码 200 的响应**，错误页不得覆盖已有好数据。
- **旧数据不设硬性保留上限**：直到被成功拉取的新数据替换为止（nginx 的缓存淘汰按最后访问时间计，页面天天有人访问就永远不会过期，无法实现"最长 7 天"）。数据是否陈旧只靠"上次同步超过 48 小时"的页面警告提示。
- **缓存目录挂成命名卷**，容器重启后缓存仍在，否则"上游故障仍可用"在重启后失效。
- **可配置项**：两个上游的 base URL、两项缓存时长、三项冷却时间都通过环境变量注入，默认值即上述生产值（这是为了让测试能用模拟上游并缩短时间）。请求体仍写死，安全目标是"客户端不能指定"，不是"运维不能配置"。nginx 默认不读环境变量，需在启动时渲染配置或通过 Lua 读取。
- 上游连接超时 5 秒、读取超时 30 秒；缓存过期瞬间的并发请求加锁，只放一个请求到上游。
- **上次同步时间**：每个缓存响应必须带一个能反映"容器最近一次成功向上游拉取的时间"的头（例如让缓存保留上游的 `Date`，而不是被 nginx 用当前时间覆盖；nginx 默认会隐藏上游的 `Date`，需要显式配置透传，或另加专用的拉取时间头）。同时暴露缓存状态头（命中、过期后仍返回旧数据、绕过缓存等），前端据此判断当前是否在显示旧数据。这是需要专门测试的行为：命中缓存后连续请求两次，拉取时间必须保持不变。
- 官方接口的响应带 Cloudflare 的 `Set-Cookie`，代理必须隐藏或忽略该头，否则该响应不会被缓存。
- 响应体较大的 BenchLM 文件（约 1.6MB 与 0.4MB）需要压缩传输。

### "立即同步"

- `POST /api/refresh` 依次处理官方榜单和 BenchLM 两个上游，各自独立判断冷却，通过冷却的才绕过缓存强制取一次；返回 JSON，每个上游一个状态：已刷新、冷却中（含还需等待的秒数）、失败（含原因）；均带完成时间。
- 冷却由服务端强制、局域网共用：官方榜单成功后 10 分钟；BenchLM 成功后 1 小时；任一上游失败后 1 分钟。冷却状态存放在容器内存里，重启后清零，可接受。
- 失败不覆盖已有缓存。
- 前端在同步前后比较官方数据的更新时间，得到"官方数据无更新（仍为 <日期>）"或"官方数据已更新"的提示；BenchLM 处于冷却时，提示里注明只刷新了官方部分。
- 同步中按钮显示"同步中…"；冷却中禁用并显示剩余时间；失败时按钮恢复可点，并显示原因与失败时间。

### 数据模型与换算（官方视图）

- 官方响应的形状异常（`rows` 不是数组）时视图模型抛出明确错误，页面显示错误面板与重试入口；`rows` 里为 null、非对象、或缺模型名、框架、档位、分数的行被丢弃并计数（`notes.dropped`），不让单行数据拖垮整张图。
- 官方每一行 = 模型 + 智能体框架 + 推理档位，带分数（0–100 的任务完成率）、95% 置信区间半宽、试验次数（当前每行 330）、总成本、输出 token、平均单次耗时、模型发布日期。
- **成本** = 该行总成本 ÷ 试验次数；**输出 token** = 该行输出 token ÷ 试验次数；**耗时**取官方给出的平均单次耗时。三者都是每次试验平均值。
- 官方行没有原始模型 ID，也没有步数字段；因此不做步数指标。
- 档位顺序：none、low、medium、high、xhigh、max。同一模型加同一框架的各档位按此顺序连线；线的颜色按厂商分色系，档位越高颜色越深。
- 官方视图**不使用** BenchLM 的价格或映射表：成本来自官方，发布日期官方行自带。

### 官方视图

- 顶部数据源切换：官方榜单 | 补充。官方视图下再有指标切换：成本 | 输出 token | 耗时，默认成本。
- X 轴反向线性（越小越靠右），Y 轴为分数，从 0 起。
- 默认显示全部榜单行；可切换为"每个模型只取最佳档"（分数最高，分数相同取 X 值更小者）；分组按"模型加智能体框架"，即同一模型在不同框架下各取一个（当前数据里每个模型只有一个框架，两种口径结果相同；保留框架维度是为了不把另一个框架的行整体藏起来）。
- 筛选下拉：按模型勾选（含半选状态）、每个模型下有档位小按钮；没有数据的档位划掉且不可点；显示"已选/总数"；提供全选与清空。
- 悬停内容：模型、框架、档位、分数 ± 置信区间、成本、输出 token、耗时、发布日期。默认不画误差线。
- **最优前沿**：在当前选中的指标（X 越小越好）与分数（越大越好）上，一个点若存在另一个点 X 不更大、分数不更低且至少一项严格更优，则被压制；未被压制的点构成前沿。完全相同的点都留在前沿上。前沿线要画出来，前沿上的点加粗。前沿只在**当前可见的点**（应用筛选与"最佳档"开关之后）上计算。
- **预算档小表**只在指标为成本时显示：≤$5、≤$10、≤$15 三档（累计阈值）；每档给出可见点里分数最高的榜单行；分数并列时并列显示，成本更低者靠前；该档没有点时显示"—"。

### 补充视图

- 数据：Artificial Analysis 的 Terminal-Bench 4.0 分数（BenchLM 模型文件里对应的分数字段）。只收同时有正的输出单价的模型；无价格模型不画，图注写明排除数量并可悬停查看名单。
- Y 轴为该分数，X 轴为输出单价（美元每百万 token），**对数刻度且反向**（价格跨好几个数量级）；每个模型一个点，没有档位连线。官方视图的 X 轴仍是线性反向。
- 用不同形状标出"官方榜单也收录了此模型"，判断依据是一张仓库内的模型映射表（官方模型名到 BenchLM slug，约 15 项）；映射缺失时静默不标记，并在浏览器控制台记一条警告。
- 只画最优前沿线（按单价），**不做预算档小表**。
- 只提供按厂商筛选，不做按地区筛选。悬停显示模型、厂商、分数、单价、发布日期。

### 页面信息与说明文字

- 顶部信息行（官方视图）：榜单行数、每行试验次数（取自数据的 `n_trials`，当前 330）、官方数据更新于 <日期>、上次同步 <相对时间>、"立即同步"按钮。官方接口没有任务数字段（66 个任务只出现在 BenchLM 页面文字里），因此不显示任务数。"官方数据更新于"取官方榜单各行更新时间的最大值；"上次同步"取上述拉取时间头。补充视图的顶部信息行显示 BenchLM 快照日期与上次同步时间。
- 仅当"上次同步"超过 48 小时才显示黄色警告；官方数据本身的新旧只中性显示。
- 官方视图：
  - X 轴标题"平均每任务成本（美元，实测）ⓘ"，悬停："成本 = 官方榜单公布的该行 330 次试验总成本 ÷ 330。官方未说明计价口径（是否按公开单价、是否含缓存折扣），不同厂商之间可能不完全可比。每一行是'模型 + 框架 + 档位'的整套结果，不是模型单价。"其中试验次数取数据里的值。
  - Y 轴标题"Terminal-Bench 4.0 分数（任务完成率）"。
  - 图下注："分数接近的行在统计上分不出高下：每行有 95% 置信区间（悬停查看），约 ±<最小值> 到 ±<最大值> 个百分点。"数字取当前数据的最小与最大半宽，不写死。
  - 前沿线图例："最优前沿：没有'成本更低且分数更高'的行"。
  - 图下注："官方榜单只收录维护者评测过的模型；未收录且有公开价格的（如 DeepSeek、Kimi、MiniMax）请看「补充」视图。无公开价格的开源或自托管模型（如 Qwen、GLM 的部分型号）两个视图都无法绘制。"

  - 顶部常驻横幅："分数来自 Artificial Analysis 的独立评测（经 BenchLM 数据集提供），评测设置与官方榜单不同，不可与官方视图直接比较。"

### 模块

- **缓存代理层**：容器配置加一小段 Lua，负责三个代理接口、白名单、缓存与冷却。
- **视图模型模块（纯函数）**：输入原始官方数据、BenchLM 数据、模型映射表和筛选状态，输出要画的点、连线、最优前沿、预算档表、顶部信息行所需的日期与提示状态。所有换算和最优前沿计算都在这里，不接触浏览器。
- **渲染层**：用 D3 把视图模型画成图，处理悬停、筛选下拉、指标与视图切换、主题、按钮交互；不含业务计算。
- **模型映射数据**：一份小型静态数据，仅供补充视图的形状标记使用。

## Testing Decisions

- 好测试只验证外部行为：给定输入数据和操作，应该看到什么输出或页面状态；不断言内部函数如何组织、D3 如何绘制。
- **主接缝**：运行中的容器。用两个模拟上游（分别模拟官方榜单和 BenchLM，数据用我们已保存的真实上游样例）替代真实上游，通过 HTTP 与一个浏览器烟雾测试验证：
  - 两个代理接口返回预期数据；白名单外的路径被拒绝；请求体不能由客户端指定；
  - 缓存生效（缓存期内上游只收到一次请求）；上游超时或 5xx 时返回旧数据；
  - 带 `Set-Cookie` 的上游响应仍被缓存；
  - 刷新接口的冷却（官方 10 分钟、BenchLM 1 小时、失败 1 分钟）、冷却期内的拒绝与剩余秒数、失败不覆盖旧缓存；
  - 页面能加载并显示数据日期、"立即同步"按钮的各种反馈（已更新、无更新、冷却中、失败）。
- **辅助接缝**：视图模型模块。用真实样例数据覆盖：成本、token、耗时换算；档位排序与连线分组；"最佳档"取舍与并列；最优前沿（并列点、相同点、同 X 更高 Y、同 Y 更低 X）；预算档表（并列、空档、指标非成本时隐藏）；筛选状态（半选、无数据档位）；补充视图的无价格排除、◆ 标记、映射缺失；置信区间范围计算；数据日期与 48 小时警告规则。
- 模拟上游是 http，真实上游是 https 加服务器名指示，所以**还需要一次对真实上游的烟雾测试**（手动或单独的可选测试）：确认容器内 DNS 解析、TLS、Cloudflare 不拦截服务端请求、`Set-Cookie` 处理后响应能被缓存。这一步要在写模拟上游之前先做。
- 缓存与冷却测试通过环境变量缩短时间，不真等 6 小时或 1 小时。
- 不测：D3 画出的具体像素和样式，只用烟雾测试确认"能画出来"。
- 先例：项目是全新的，没有既有测试；真实上游样例数据可作为测试夹具。
